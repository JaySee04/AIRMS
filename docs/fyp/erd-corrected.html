Eight tables. injuries and self_reports were dropped on 2026-08-02 with the HoloMotion-only cut; activities and recovery_baselines on 2026-07-20 with Activity Tracking. What remains of injury state is five columns on athletes (is_injured … norm_excluded), set by a clinician and read by the cohort-norm eligibility rule. athletes.athlete_id is the cross-table key throughout, and since 2026-08-04 its values are the athlete's 12-digit identity-card number; the column name and its role are unchanged, and the API serialises it as _id. users.athlete_id is a deliberate soft link rather than an enforced constraint, so seeding order cannot deadlock. screenings is append-only — one immutable row per committed import, which is what makes history, progress deltas and the cohort norms possible; athletes holds only the latest values. The two dashed links are derivations, not foreign keys: a cohort is identified by the values (sport, programme, gender, discipline, tier) rather than by a reference, and a norm version stores a JSON snapshot of every cohort row rather than pointing at them — which is precisely what lets a restore reinstate cohorts that have since been recomputed or deleted.
