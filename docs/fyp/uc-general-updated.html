Use Case Diagram — General Module

added since the FYP I decomposition
Profiles are view-only plus in-place change-password; identity fields (name, age, gender, sport, programme) are maintained through the Module 3 (Screening Data Ingestion) import or by the administrator, not self-service — there is no self-registration (accounts are provisioned). All five roles have the full account surface: login, password reset, in-place change-password, profile and per-user notification preferences. Manage Personnel & Permissions is one administrator capability covering all four invitable roles — creating a medical, coach, administrator or executive account, assigning or changing a coach's single sport, and granting or revoking a medical staffer's individual capabilities. An account is created with no usable password: one is generated, hashed and discarded unread, and the person sets the first real password from a one-time code (Invite User → Activate Account), so nobody — including the administrator who created it — can sign in as them. Per-user permissions are an opt-out model: a capability is granted unless explicitly revoked, and on revocation the system blocks it server-side while the feature disappears from that staffer's interface on their next navigation.
